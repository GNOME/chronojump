About Python & R:
Please download and install Python and R from their official website in order to copy them from local drive while making packages. As a result, we don't need to put them in Git.

Python: https://www.python.org/ftp/python/3.12.2/python-3.12.2-macos11.pkg

R:
check R is not installed before, could be a problem on making the package if uses other version, as the version is going to be signed is one of these:
https://cran.r-project.org/bin/macosx/big-sur-x86_64/base/R-4.3.3-x86_64.pkg
https://cran.r-project.org/bin/macosx/big-sur-arm64/base/R-4.3.3-arm64.pkg

6. About the Apple Certs:

(1) Download the 3 intermediate certificates:

https://www.apple.com/certificateauthority/AppleWWDRCAG3.cer

https://www.apple.com/certificateauthority/AppleWWDRCAG4.cer

https://www.apple.com/certificateauthority/DeveloperIDG2CA.cer

(2) Download the Developer ID Application Cert and Developer ID Installer Cert (They are used by dmg and pkg out of Apple Store). Download the 3rd Party Mac Developer Application Cert and 3rd Party Mac Developer Installer Cert (They are used by pkg in Apple Store).

(3) Double-click them and install them into "Keychain Access"/"Login". (Only the first time)

#Unlock the keychain, please replase {user} with your real macOS user name (Only the first time)
sudo security unlock-keychain /Users/{user}/Library/Keychains/login.keychain-db

#Execute this command to check whether the certificates are installed correctly, please replase {user} with your real macOS user name (Only the first time)
sudo security find-identity codesigning /Users/{user}/Library/Keychains/login.keychain-db

(4) On KeyChain app select all the Apple Certs and click on Evaluate and then on generic (not signing, generic). Confirm the result is correct and good.

(5) On KeyChain app where there is a blue/white icon of a + sign, click on Get Info and there change the Always Trust to Use System Defaults. Then the blue/white + icon disappeared but on KeyChain it says it is correct.

7. Make a package (Only when a package required)

cd "~/Desktop/chronojump/package/macos"
make dmg #Execute this command to create *.dmg package.
make pkg #Execute this command to create *.pkg package which is distributed out of Apple Store.
make pkg PLACE="apple-store" #Execute this command to create *.pkg package which is distributed in Apple Store. It's not working now while we use GTK3.
#If it says "permission denied", please remove "package/macos/app/Chronojump.app" first. It would fail while uploading to Apple Store Conenct with "sudo".

For making an arm64 package using Microsoft.Data.Sqlite, execute the following commands:
make dmg SQLITE_LIB="Microsoft.Data.Sqlite" #Execute this command to create *.dmg package.
make pkg SQLITE_LIB="Microsoft.Data.Sqlite" #Execute this command to create *.pkg package which is distributed out of Apple Store. It's not working now while we use GTK3.
make pkg PLACE="apple-store" SQLITE_LIB="Microsoft.Data.Sqlite" #Execute this command to create *.pkg package which is distributed in Apple Store.

#Python bundle executable: Resources/Python-x64/Versions/Current/bin/python3
#R bundle executable: Resources/R-x64/Resources/R Resources/R-x64/Resources/Rscript

#While uploading to Apple Store, you could use the following command to verify the *.pkg (Please replace "AppleId" and "AppleAppSpecificPassword" with real Apple credentials and use the real pkg file name):
xcrun altool --validate-app -f *.pkg -t osx -u AppleId -p AppleAppSpecificPassword

8. If the final notarizing status is invalid, please execute the following command to check the detail error logs:

xcrun notarytool log --apple-id=${APPLE_ID} --password ${APPLE_PASSWORD} --team-id ${APPLE_TEAM_ID} uuid

#Please replace ${APPLE_ID}, ${APPLE_PASSWORD} and ${APPLE_TEAM_ID} with the Apple ID, Apple ID app-specific password and Apple Team ID. The last parameter "uuid" is the uuid shown while notarizing.
